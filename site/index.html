03CONNECT

サービスへ、直接つながる。

Headscale・Gitea・TailscaleなどのサービスごとにOIDCクライアントを設定し、Kituneと直接連携します。複数のKituneをまとめるときだけ、家族・サークル用の共有Dexを組み合わせます。

認証の構成を見る ↗
BUILT ON OIDC

認可コード、S256方式のPKCE、ローテーションに対応したリフレッシュトークンを利用できます。接続先は、クライアントシークレットを保持できるWebサーバーです。require_pkceを省略した場合は、S256方式のPKCEが必須です。PKCEに対応していないサービスに限り、クライアントごとにrequire_pkce = falseを指定できます。公開クライアントには対応していません。

DIRECT OIDC CONNECTIONS

使うサービスへ、
Kituneから。

サービスごとに別のクライアントIDとシークレットを登録します。基本スコープはopenid profile email、認証方式はclient_secret_basicが既定です。必要に応じてclient_secret_postも選べます。実サービスへの接続確認は利用環境で行い、ここでは設定例と互換性の範囲を示します。

01TAILSCALE

Tailscale

互換性確認用の初期例です。WebFingerのissuerとDiscoveryのissuerを一致させ、まずBasic認証で接続します。

id = "tailscale"
name = "Tailscale"
redirect_uris = ["https://login.tailscale.com/a/oauth_response"]
secret_env = "TAILSCALE_CLIENT_SECRET"
scopes = ["openid", "profile", "email"]
require_pkce = false
callback
https://login.tailscale.com/a/oauth_response
issuer
https://id.example.com/api/auth（WebFingerとDiscoveryで一致）
確認状況
実サービスへの接続とPKCE送信の挙動は未確認

Headscale

id = "headscale"

redirect_uris = ["https://headscale.example.com/oidc/callback"]
secret_env = "HEADSCALE_CLIENT_SECRET"
scopes = ["openid", "profile", "email"]
# require_pkceを省略した場合はS256方式のPKCEが必須
callback
https://headscale.example.com/oidc/callback
Headscale側
pkce.enabled: true / method: S256
03GITEA 1.27.3

Gitea

外部OIDCクライアントがPKCE・nonceを送らないため、このクライアントだけ例外にします。

id = "gitea"
name = "Gitea"
redirect_uris = ["https://gitea.example.com/user/oauth2/kitune/callback"]
secret_env = "GITEA_CLIENT_SECRET"
scopes = ["openid", "profile", "email"]
require_pkce = false
認証ソース
kitune
callback
https://gitea.example.com/user/oauth2/kitune/callback
注意
offline_accessは付けません

直接接続時のsubはKituneで設定した固定ユーザーIDです。groupsには、personalなどKituneで設定した値をそのまま返します。複数の認証元をまとめる場合は、共有Dexも利用できます。

GET STARTED

まずは、
自分の端末から。

Bun 1.4.2を用意して、
ローカルでKituneを動かしてみましょう。

READMEで手順を読む ↗
LOCAL DEVELOPMENThttp://localhost:3000

Passkeyを使うため、ホスト名は
localhostを指定します。

  1. 1

    取得して、設定を用意する

    TERMINAL
    git clone https://github.com/glyzinie/Kitune.git
cd Kitune
cp config.example.toml config.toml
cp .env.example .env
bun install --frozen-lockfile
  2. 2

    自分の設定で、起動する

    config.tomlのユーザー・クライアントを編集します。.envのBETTER_AUTH_SECRETと、各クライアントのsecret_envで指定した環境変数に、それぞれ32文字以上のシークレットを設定します。シークレットはopenssl rand -hex 32などで個別に生成してください。require_pkceを省略した場合は、S256方式のPKCEが必須です。PKCEに対応していないサービスに限り、require_pkce = falseを指定します。

    TERMINAL
    bun run cli check-config
bun run dev
  3. 3

    最初のPasskeyを登録する

    別のターミナルで実行し、表示されたURLをブラウザで開きます。ownerは設定したユーザーIDに置き換えてください。登録URLは発行から15分間有効です。登録が完了すると再利用できなくなります。

    ANOTHER TERMINAL
    bun run cli enroll owner
